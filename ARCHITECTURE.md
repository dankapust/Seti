# Архитектура программного комплекса

Документ описывает структуру проекта, распределение ответственности между модулями и принятые инженерные решения.

### 1. Логические модули
Проект разделен на слабо связанные пакеты для изоляции транспортного уровня от прикладного алгоритма Kademlia:
* **`transport/`**: Модули `connection.py` и `frame.py`. Отвечают за чтение потока байт из TCP-сокета, буферизацию, контроль тайм-аутов и `MAX_FRAME_PAYLOAD`, упаковку и распаковку 24-байтовых заголовков кадра.
* **`protocol/`**: Хранит константы (`PROTOCOL_VERSION`, размер заголовка) и `Enum` структур для типов сообщений.
* **`identity/`**: Генерация и хранение долговременных ключей Ed25519. Связывает пару ключей и `NodeID`.
* **`routing/`**: Модуль, содержащий логику `Contact`, XOR-расстояния и `RoutingTable` с `KBucket`.
* **`rpc/`**: Обработчики запросов Kademlia (`kademlia.py`), реализующие валидацию удаленных контактов и ответы на PING/FIND_NODE.
* **`node/`**: Координатор узла (`kademlia_node.py`). Инициализирует сервер, запускает диспетчер сообщений и реализует итеративный параллельный поиск и сценарий присоединения (Bootstrap).

### 2. Выбранные инженерные решения
* **TCP concurrency:** Использован фреймворк `asyncio`. Для каждого входящего запроса создается асинхронная корутина. Исходящие запросы при Lookup используют `asyncio.gather` для обеспечения параллелизма (строго 3 потока по константе `ALPHA`).
* **Защита от фрагментации:** Транспорт не полагается на размер пакета на уровне ОС. Реализовано строгое чтение через `readexactly(HEADER_SIZE)` и `readexactly(payload_length)`. Выделение памяти под payload происходит **только** после проверки длины на превышение `MAX_FRAME_PAYLOAD`.
* **Криптография:** Используется библиотека `cryptography`. Приватные ключи сохраняются в файловой системе локально (`NODE_STATE_DIR`).

### 3. Маршрутизация и K-buckets
Таблица маршрутизации реализована в виде массива из 256 фиксированных корзин (K-Buckets).
* **Индекс корзины** определяется позицией старшего установленного бита в XOR-расстоянии между локальным `NodeID` и удаленным `NodeID`.
* **Емкость корзины** ограничена параметром `K_BUCKET_SIZE` (в текущей конфигурации 4).
* **Политика вытеснения:** Сортировка Least Recently Used (LRU). Контакты добавляются в конец корзины. В случае нехватки места, контакт на индексе `0` (самый старый) должен быть проверен PING-ом, прежде чем быть вытесненным.
