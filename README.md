# Защищённая оверлейная сеть передачи данных на основе пиринговых протоколов

Учебный прототип P2P-сети, реализующий TCP-транспорт, строгий бинарный фрейминг, криптографическую идентичность на основе Ed25519 и DHT-маршрутизацию Kademlia. Проект реализует этапы курсовой работы.

### Запуск тестов (Этапы 1, 2 и 3)
В проекте реализован полный набор unit- и integration-тестов (25 тестов):
* **Транспортный уровень (`test_framing.py`, 8 тестов):** 24-байтовый заголовок, сериализация MessagePack, лимит `MAX_FRAME_PAYLOAD`, склейка и фрагментация TCP, независимые параллельные порты, таймауты `ReadTimeoutError`, обработка ошибок диспетчером.
* **Маршрутизация Kademlia (`test_kademlia.py`, 10 тестов):** генерация и детерминизм ключей Ed25519, защита от подмены открытого ключа, аксиомы XOR-метрики и ультраметрика, статистика заполненности корзин, емкость K-Bucket, вытеснение недоступного кандидата `oldest`, сохранение активного `oldest`, итеративный `lookup_node` с полным опросом кандидатов, Star Bootstrap и каскадный Chain Bootstrap.
* **Хранилище и репликация (`test_storage_and_replication.py`, 7 тестов):** подписи Ed25519 в `NodeRecord`, защита от инъекций и подмены ключа, соблюдение TTL, защита от атак отката (Rollback protection по `sequence_number`), RPC `STORE`/`FIND_VALUE`, кворум репликации ($W \ge 2$), контрольный поиск записи после отказа хранителя.

**Локальный запуск всех тестов:**
```bash
pip install -r requirements.txt
python -m pytest tests/ -v
```

**Запуск тестов через Docker:**
```bash
docker-compose up --build tests
```

### Запуск демонстрационных сценариев

#### Сценарий Этапа 1 (`demo_stage1.py`)
Демонстрирует работу 3 независимых одновременных узлов на портах 8001, 8002 и 8003:
1. Параллельный перекрестный обмен кадрами PING/PONG через `asyncio.gather`.
2. Контролируемую обработку таймаута при задержке ответа от узла Node_C с возбуждением `ReadTimeoutError`.

**Запуск:**
```bash
python demo_stage1.py
```
*(Логи сохраняются в `logs/stage1_demo.log`)*

#### Сценарий Этапа 2 (`demo_stage2.py`)
Демонстрирует вытеснение `oldest` при переполнении K-Bucket, распределение корзин, подключение сети через Star Bootstrap (5 узлов) и каскадный Chain Bootstrap (4 узла) с многохоповым поиском узлов.

**Запуск:**
```bash
python demo_stage2.py
```
*(Логи сохраняются в `logs/stage2_demo.log`)*

#### Сценарий Этапа 3 (`demo_stage3.py`)
Демонстрирует создание и валидацию подписанной `NodeRecord` (Ed25519), защиту от подделки и отката версий (`sequence_number`), реплицированное сохранение `STORE` на $R=3$ узла с кворумом, отказ одного из узлов-хранителей и успешный последующий `FIND_VALUE` с живых реплик, а также автоматическое истечение и удаление записей по TTL.

**Запуск:**
```bash
python demo_stage3.py
```
*(Логи сохраняются в `logs/stage3_demo.log`)*
