# Защищённая оверлейная сеть передачи данных на основе пиринговых протоколов

Учебный прототип P2P-сети, реализующий TCP-транспорт, строгий бинарный фрейминг, криптографическую идентичность на основе Ed25519 и DHT-маршрутизацию Kademlia. Проект реализует этапы курсовой работы.

### Запуск тестов (Этапы 1, 2, 3, 4 и 5)
В проекте реализован полный набор unit-, integration- и negative-тестов (**90 автоматических тестов**):
* **Транспортный уровень (`test_framing.py`, 15 тестов):** 24-байтовый заголовок, сериализация MessagePack, лимит `MAX_FRAME_PAYLOAD = 64KB` до аллокации, склейка и фрагментация TCP, независимые параллельные порты, таймауты `ReadTimeoutError`, обработка ошибок диспетчером (`ERROR`).
* **Криптографическая идентичность (`test_identity.py`, 10 тестов):** генерация и детерминизм ключей Ed25519, соответствие `NodeID = SHA-256(RawPublicKey)`, валидация подписей, защита от искажений и подделок.
* **Маршрутизация Kademlia и персистентность (`test_kademlia.py`, 22 теста):** защита от подмены открытого ключа (Anti-Spoofing), аксиомы XOR-метрики и ультраметрика, статистика заполненности корзин, емкость K-Bucket, вытеснение недоступного кандидата `oldest`, сохранение активного `oldest` (закон Парето), итеративный `lookup_node` с полным опросом кандидатов, Star Bootstrap, каскадный Chain Bootstrap, сохранение и восстановление таблицы маршрутизации с диска (E2-7).
* **Хранилище и репликация (`test_storage_and_replication.py`, 15 тестов):** подписи Ed25519 в `NodeRecord`, каноническая сериализация, защита от инъекций и подмены ключа, соблюдение TTL, защита от атак отката (Rollback protection по `sequence_number`), RPC `STORE`/`FIND_VALUE`, кворум репликации ($W \ge 2$), контрольный поиск записи после отказа хранителя.
* **Защищенный канал связи (`test_secure_channel.py`, 20 тестов):** асимметричный обмен ключами X25519 ECDH (PFS), взаимная аутентификация Ed25519, деривация сессионных ключей HKDF-SHA256, симметричный шифр ChaCha20-Poly1305 AEAD, аутентификация заголовка через AAD, детекция и блокировка Replay-атак по 64-битным счетчикам.
* **Многопереходные туннели (`test_tunnel.py`, 8 тестов):** построение туннелей через $\ge 2$ ретранслятора, сквозное шифрование End-to-End, сквозные подтверждения `TUNNEL_ACK`, дедупликация сообщений, детекция отказа ретранслятора и автоматическое перестроение туннеля через альтернативный узел.

**Локальный запуск всех тестов:**
```bash
pip install -r requirements.txt
python -m pytest tests/ -v
```

**Запуск тестов через Docker:**
```bash
docker-compose run --rm tests
```

### Запуск демонстрационных сценариев

#### Сценарий Этапа 1 (`demos/demo_stage1.py`)
Демонстрирует работу 3 независимых одновременных узлов на портах 8001, 8002 и 8003:
1. Параллельный перекрестный обмен кадрами PING/PONG через `asyncio.gather`.
2. Контролируемую обработку таймаута при задержке ответа от узла Node_C с возбуждением `ReadTimeoutError`.

```bash
python demos/demo_stage1.py
```

#### Сценарий Этапа 2 (`demos/demo_stage2.py`)
Демонстрирует вытеснение `oldest` при переполнении K-Bucket, распределение корзин, подключение сети через Star Bootstrap (5 узлов), каскадный Chain Bootstrap (4 узла) с многохоповым поиском узлов и персистентность таблицы маршрутизации (сохранение на диск и восстановление при рестарте).

```bash
python demos/demo_stage2.py
```

#### Сценарий Этапа 3 (`demos/demo_stage3.py`)
Демонстрирует создание и валидацию подписанной `NodeRecord` (Ed25519), защиту от подделки и отката версий (`sequence_number`), реплицированное сохранение `STORE` на $R=3$ узла с кворумом, отказ одного из узлов-хранителей и успешный последующий `FIND_VALUE` с живых реплик, а также автоматическое истечение и удаление записей по TTL.

```bash
python demos/demo_stage3.py
```

#### Сценарий Этапа 4 (`demos/demo_stage4.py`)
Демонстрирует установление защищенной сессии X25519 ECDH + HKDF-SHA256, шифрование прикладного потока ChaCha20-Poly1305 AEAD, перехват сырых пакетов сниффером (0 байт утечки открытого текста), а также мгновенное блокирование попыток Replay-атак и модификации шифртекста.

```bash
python demos/demo_stage4.py
```

#### Сценарий Этапа 5 (`demos/demo_stage5.py`)
Демонстрирует построение 2-переходного туннеля через независимые ретрансляторы (`Alice -> R1 -> R2 -> Bob`), передачу сквозных зашифрованных данных (ретрансляторы не имеют ключей и видят только шифртекст), аварийное отключение ретранслятора R2 и автоматическое мгновенное перестроение маршрута через запасной узел R3.

```bash
python demos/demo_stage5.py
```
