# Руководство пользователя (Этапы 1–3)

На текущих этапах (1, 2 и 3) проект представляет собой рабочий прототип защищенной децентрализованной P2P-сети Kademlia с хранилищем подписанных записей и отказоустойчивой репликацией.

---

## 1. Конфигурация узла
Параметры узла задаются в файле `config/default.json`. Основные параметры:
* `LISTEN_PORT`: порт, на котором узел ожидает входящие TCP-соединения.
* `K_BUCKET_SIZE`: размер корзины маршрутизации (k-bucket, по умолчанию 4).
* `ALPHA`: уровень параллелизма при Kademlia lookup (по умолчанию 3).
* `CONNECT_TIMEOUT_MS` / `READ_TIMEOUT_MS`: лимиты времени ожидания сетевых операций.

---

## 2. Запуск интеграционных тестов (Этапы 1–3)
Чтобы убедиться в корректности транспортного слоя, DHT-маршрутизации, криптографических подписей и репликации:

```bash
python -m pytest tests/ -v
```
Все 25 тестов должны завершиться со статусом **PASSED**.

---

## 3. Демонстрация Этапа 1 (`demo_stage1.py`)
Демонстрирует требования критериев E1-1 — E1-8:
* Независимые процессы на портах 8001, 8002 и 8003.
* Одновременный параллельный обмен сообщениями.
* Диагностика таймаута с генерацией `ReadTimeoutError`.

```bash
python demo_stage1.py
```

---

## 4. Демонстрация Этапа 2 (`demo_stage2.py`)
Разворачивает локальную тестовую сеть Kademlia:
1. **Проверка вытеснения:** зонд `oldest` при переполнении корзины.
2. **Bootstrap Схема 1 (Star):** 5 узлов подключаются к Seed-узлу (порт 9000).
3. **Контрольный Lookup:** итеративный опрос всех кандидатов без преждевременной остановки.
4. **Bootstrap Схема 2 (Chain):** каскадное подключение $N_3 \to N_2 \to N_1 \to N_0$ с многохоповой сходимостью.

```bash
python demo_stage2.py
```

---

## 5. Демонстрация Этапа 3 (`demo_stage3.py`)
Демонстрирует операции хранения, криптографические подписи и отказоустойчивость репликации:
1. **Криптографическая NodeRecord:** генерация и проверка подписи Ed25519.
2. **Защита от атак:** отклонение невалидных подписей и попыток отката версии (`sequence_number`).
3. **Реплицированный STORE:** сохранение записи на $R=3$ узла с подтверждением кворума $W \ge 2$.
4. **Поиск после отказа хранителя:** отключение одного из узлов-хранителей и успешный `FIND_VALUE` с оставшихся реплик.
5. **Соблюдение TTL:** автоматическая аннуляция просроченной записи.

```bash
python demo_stage3.py
```
Журналы выполнения сохраняются в директорию `./logs/`.
