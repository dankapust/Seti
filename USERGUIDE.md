# Руководство пользователя (Этапы 1–2)

На текущих этапах (1 и 2) проект представляет собой рабочий прототип транспортного и маршрутизирующего слоёв децентрализованной P2P-сети Kademlia.

---

## 1. Конфигурация узла
Параметры узла задаются в файле `config/default.json`. Основные параметры:
* `LISTEN_PORT`: порт, на котором узел ожидает входящие TCP-соединения.
* `K_BUCKET_SIZE`: размер корзины маршрутизации (k-bucket, по умолчанию 4).
* `ALPHA`: уровень параллелизма при Kademlia lookup (по умолчанию 3).
* `CONNECT_TIMEOUT_MS` / `READ_TIMEOUT_MS`: лимиты времени ожидания сетевых операций.

---

## 2. Запуск интеграционных тестов (Этапы 1–2)
Чтобы убедиться в корректности транспортного слоя и DHT-маршрутизации (кадрирование, защита от переполнения, тайм-ауты, вытеснение oldest, итеративный lookup):

```bash
python -m pytest tests/ -v
```
Все 15 тестов должны завершиться со статусом **PASSED**.

---

## 3. Демонстрация Этапа 1 (`demo_stage1.py`)
Демонстрирует требования критериев E1-1 — E1-8:
* Независимые процессы на портах 8001, 8002 и 8003.
* Одновременный параллельный обмен сообщениями.
* Диагностика таймаута с генерацией `ReadTimeoutError`.

```bash
python demo_stage1.py
```

---

## 4. Демонстрация Этапа 2 (`demo_stage2.py`)
Разворачивает локальную тестовую сеть из 5 независимых узлов:
1. **Инициализация:** генерация уникальных Ed25519-ключей в `./state/`.
2. **Bootstrap:** узлы подключаются к Seed-узлу (порт 9000), обмениваются PING и выполняют self-lookup.
3. **Контрольный Lookup:** узел-инициатор находит целевой узел в DHT, доказывая сходимость таблицы маршрутизации.

```bash
python demo_stage2.py
```
Журналы выполнения сохраняются в директорию `./logs/`.
