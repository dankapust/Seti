# Руководство пользователя (Этапы 1–2)

На текущих этапах (1 и 2) проект представляет собой прототип транспортного и маршрутизирующего слоёв P2P-сети Kademlia. Полноценный пользовательский интерфейс (CLI/API) для работы с файлами и туннелями будет добавлен на следующих этапах. 

Взаимодействие с узлами на данном этапе осуществляется через конфигурационные файлы и автоматизированные сценарии.

## 1. Конфигурация узла
Перед запуском узла убедитесь, что параметры в `config/default.json` настроены корректно. Основные параметры, которые можно менять для экспериментов:
* `LISTEN_PORT`: порт, на котором узел будет ожидать входящие TCP-соединения.
* `K_BUCKET_SIZE`: размер корзины маршрутизации (рекомендуется 3 или 4 для малых тестовых сетей).
* `ALPHA`: уровень параллелизма при поиске узлов (по умолчанию 3).

## 2. Запуск интеграционных тестов
Чтобы убедиться в работоспособности транспортного слоя (кадрирование, защита от переполнения, тайм-ауты), выполните:

python -m pytest tests/test_framing.py -v

Все тесты должны завершиться со статусом PASSED.

3. Запуск демо-сценария Kademlia
Для демонстрации работы алгоритма маршрутизации (создание ключей, bootstrap, k-buckets и итеративный поиск) предусмотрен готовый сценарий, который разворачивает локальную сеть из 5 независимых узлов.

Выполните команду:

python demo_stage2.py

Как интерпретировать результаты скрипта:
Инициализация: Скрипт очищает директорию ./state/, чтобы сгенерировать новые уникальные криптографические ключи Ed25519 для каждого из 5 узлов.

Bootstrap: Вы увидите в консоли, как узлы с портами 9001-9004 поочередно подключаются к seed-узлу (порт 9000), отправляют PING и выполняют процедуру self-lookup для заполнения своих таблиц маршрутизации.

Контрольный Lookup: В конце сценария узел-инициатор попытается найти целевой узел, которого изначально не было в его локальной таблице. Вывод ✅ УСПЕХ: Узел ... успешно нашел ... через DHT! подтверждает, что децентрализованный поиск работает корректно.

Подробные логи каждого взаимодействия, включая отправленные RPC-запросы и метрики времени, сохраняются в директорию ./logs/.
