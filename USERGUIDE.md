# Руководство пользователя (Этапы 1–5)

Проект представляет собой законченную реализацию защищенной децентрализованной оверлейной P2P-сети на базе протокола Kademlia DHT, включающую:
* **Этап 1:** Сетевой транспорт поверх TCP, бинарный 24-байтовый заголовок кадра, сериализацию MessagePack, таймауты `ReadTimeoutError` и обработку ошибок диспетчером (`ERROR`).
* **Этап 2:** Криптографическую идентичность Ed25519, вычисление $\text{NodeID} = \text{SHA-256}(\text{RawPublicKey})$, 256 K-Buckets ($k=4, \alpha=3$), вытеснение `oldest` по закону Парето, полный опрос в Lookup, схемы Bootstrap (Star и Chain) и персистентность таблицы маршрутизации на диске.
* **Этап 3:** Реплицированное хранилище `NodeRecord` с цифровыми подписями Ed25519, защиту от атак отката (`sequence_number`), мажоритарный кворум записи $W = 2$ при $R = 3$, толерантность к отказу узлов-хранителей и автоматический TTL.
* **Этап 4:** Защищенный криптографический канал X25519 ECDH + HKDF-SHA256, шифр ChaCha20-Poly1305 AEAD, заголовок кадра как AAD и Replay Shield с монотонными 64-битными счетчиками.
* **Этап 5:** Многопереходные оверлейные туннели ($\ge 2$ хопа) с E2E-шифрованием, сквозным подтверждением доставки `TUNNEL_ACK`, детекцией сбоя ретранслятора и автоматическим перестроением туннеля через альтернативный узел.

---

## 1. Конфигурация узла

Параметры узла задаются в конфигурационном файле `config/default.json`. Основные параметры:
* `NODE_STATE_DIR`: директория для сохранения локального состояния и таблицы маршрутизации (`routing_table.msgpack`).
* `LISTEN_HOST`: адрес сетевого интерфейса (по умолчанию `"0.0.0.0"`).
* `LISTEN_PORT`: TCP-порт для входящих соединений.
* `BOOTSTRAP_PEERS`: список известных узлов для начального входа в сеть (`[{"host": "...", "port": ...}]`).
* `K_BUCKET_SIZE`: емкость корзины маршрутизации ($k=4$ для учебного стенда).
* `ALPHA`: степень параллелизма Kademlia Lookup ($\alpha=3$).
* `CONNECT_TIMEOUT_MS`: таймаут сетевого подключения (мс).
* `READ_TIMEOUT_MS`: таймаут чтения заголовка и полезной нагрузки (мс).
* `MAX_FRAME_PAYLOAD`: жесткий лимит полезной нагрузки (64 КБ = 65 536 байт) до аллокации буфера.

## 4. Демонстрация Этапа 1 (`demos/demo_stage1.py`)

Демонстрирует требования критериев E1-1 — E1-8:
* Поднятие 3 независимых TCP-узлов на портах 8001, 8002 и 8003.
* Одновременный параллельный обмен сообщениями PING/PONG через `asyncio.gather`.
* Диагностику таймаута с генерацией исключения `ReadTimeoutError` и корректным закрытием сокетов.

```bash
python demos/demo_stage1.py
```

---

## 5. Демонстрация Этапа 2 (`demos/demo_stage2.py`)

Разворачивает локальную тестовую сеть Kademlia:
1. **Зондирование и вытеснение (E2-6):** опрос `oldest` при переполнении K-Bucket. Живой контакт сохраняется, мертвый вытесняется.
2. **Bootstrap Схема 1 (Star, E2-8):** 5 узлов подключаются к центральному Seed-узлу (порт 9000).
3. **Инспекция корзин (E2-3):** вывод распределения контактов по K-Buckets.
4. **Контрольный Lookup (E2-4):** итеративный опрос всех кандидатов без преждевременной остановки.
5. **Bootstrap Схема 2 (Chain, E2-8):** каскадное подключение $N_3 \to N_2 \to N_1 \to N_0$ со сходимостью за 2–3 мс.
6. **Персистентность (E2-7):** сохранение контактов в `routing_table.msgpack` и их восстановление при перезапуске узла.

```bash
python demos/demo_stage2.py
```

---

## 6. Демонстрация Этапа 3 (`demos/demo_stage3.py`)

Демонстрирует операции распределенного хранения, криптографические подписи и отказоустойчивость:
1. **Криптографическая NodeRecord:** генерация и проверка подписи Ed25519 (64 байта).
2. **Защита от атак:** блокировка поддельных подписей и попыток отката версии по `sequence_number`.
3. **Реплицированный STORE:** сохранение записи на $R=3$ узла с подтверждением кворума $W \ge 2$.
4. **Отказ узла-хранителя:** аварийная остановка одного из хранителей и успешный `FIND_VALUE` с оставшихся живых реплик.
5. **Соблюдение TTL:** автоматическое удаление просроченных записей узлом-хранителем.

```bash
python demos/demo_stage3.py
```

---

## 7. Демонстрация Этапа 4 (`demos/demo_stage4.py`)

Демонстрирует сквозной защищенный криптографический канал связи:
1. **Рукопожатие X25519 ECDH:** взаимная аутентификация Ed25519 и вывод сессионных ключей HKDF-SHA256 (Perfect Forward Secrecy).
2. **AEAD-шифрование ChaCha20-Poly1305:** шифрование полезной нагрузки и аутентификация заголовка (AAD).
3. **Анализ трафика (сниффер):** перехват сырых пакетов в сокете (0 байт утечки открытого текста, шестнадцатеричный дамп).
4. **Защита от Replay и искажений:** блокировка повторных пакетов по 64-битным счетчикам `seq_num` и отсечение подделок тегом Poly1305.
5. **Защищенный диалог Alice <-> Bob.**

```bash
python demos/demo_stage4.py
```

---

## 8. Демонстрация Этапа 5 (`demos/demo_stage5.py`)

Демонстрирует многопереходную туннельную передачу и отказоустойчивость доставки:
1. **Построение маршрута через $\ge 2$ ретранслятора:** `Alice -> R1 -> R2 -> Bob` (`TUNNEL_BUILD`, `TUNNEL_BUILD_OK`).
2. **Сквозная (E2E) конфиденциальность:** ретрансляторы транслируют только зашифрованные байты, не имея ключей.
3. **Сквозной контроль доставки:** подтверждение доставки кадром `TUNNEL_ACK`.
4. **Отказ ретранслятора и автоперестроение:** аварийный останов узла R2, детекция сбоя (`DEAD`), автоматическое перестроение туннеля через альтернативный узел R3 (`Alice -> R1 -> R3 -> Bob`) и успешная доставка последующих сообщений.

```bash
python demos/demo_stage5.py
```
